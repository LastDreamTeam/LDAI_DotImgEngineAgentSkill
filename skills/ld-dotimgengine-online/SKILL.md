# LD DotImgEngine Online

先确定用户要改变什么、保留什么，再生成并检查。读取相关流程即可，不必一次加载所有资料。

## 开始与参考

- 实际打开图像查看像素，核对文件可读性、尺寸和完整性。每次生成都明确传入参考图；仅在提示词里提文件名不算传图。无可用编辑服务或参考不可读时，报告该项阻碍，继续可独立完成的整理。
- 建立[参考清单](references/reference-manifest.template.json)：唯一 `current_primary`、区域证据优先级、冻结项、组件的角色自身左右与认可状态。新上传原型可按用户指示替换旧基准；不能悄悄混用旧脸与新身体，也不把助手自评记作用户认可。
- 按[创作流程](references/workflow.md)选择新设计、局部修正、光影或多视图分支。案例中的圆眼、苗条比例、白膝和三个悬浮组件只在对应角色需要时继承，不能强加给其他角色。

## 执行约束

- “图不要动，变立体”保留身份、轮廓、比例、五官结构、服装和主配色，允许光照、阴影与 AO 改变；正面也可以充分表现体积。若要求连像素值都不变，必须说明光影与硬像素约束的冲突并限定可改区域。
- 已认可脸优先保护，局部问题不默认整图重生成。硬像素保留使用原像素合成与原生尺寸验证；提示词“锁像素”没有这个保证。按[公开工具编排](references/toolchain.md)处理实际能力、异步任务、原始输出和蒙版。
- 多视图先建立一致材质，再逐张生成。参考图中的配件分解区也是结构证据；组件按角色自身坐标保持位置，透视和遮挡要合理。不能为凑数量透视穿透身体。
- 每轮只改指定视角、区域或光影，禁止擅加装甲、标识或重新设计。使用[提示词模板](references/prompt-templates.md)，根据实际工具能力填写，不固化供应商私有参数。

## 3D 资产局部修复

- 涉及网格、贴图、服装层次、腋下瑕疵、绑定准备或模型导出时，读取 [3D 修复与参考核对](references/3d-repair-workflow.md)。用户最新认可的脸、比例与配色作为锁定基线；原设、认可四视图和局部候选各按范围取证，背面专用参考不能替换正面或整体比例。
- 先区分 base color 污染、normal/roughness 残留、UV 接缝与真实几何问题，再做指定区域修复并验证不变区域。保持主要 mesh、UV、材质与既有修复；融合曲面的删面封洞、服装连接与动画变形均需独立检查。
- 外观、骨骼、权重、表情、导出和 Unity 验证分别记录状态。静态渲染、技术检查和用户视觉认可互不替代；未经实测的腋下修复或绑定仍是测试中，不能因一次成功导出宣称完成。

## 验收与交付

- 依据[验收清单](references/acceptance.md)逐张目视检查全身与局部，再检验 PNG、尺寸、哈希及保护区域。脸、虹膜/瞳孔/高光、胸饰、膝部、线缆与组件属于高风险检查项。
- 正面原文件与原始生成输出均保留，衍生正面另存。交付独立 PNG 附件，说明原生尺寸、是否裁切/重采样/重生成、视觉漂移和未通过项。没有网格不称真实同模型渲染，重采样不称原生 4K。
- 阅读[失败案例](references/failure-cases.md)定位复发问题；按[迭代约定](references/iteration.md)记录用户认可版本、变更区域、回归项和技能版本。未经用户认可不替换当前认可成果。
