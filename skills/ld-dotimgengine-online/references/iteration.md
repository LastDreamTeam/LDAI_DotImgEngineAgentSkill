# 持续迭代与认可记录

技能版本与图片版本分开：技能用语义版本，项目图片用稳定修订号与视角。任务中固定技能版本，避免一轮生成中途规则变化。

1. 开始前记录 `schema_version`、`skill_version`、唯一主参考、输入哈希、区域优先级、冻结项与本轮允许变化。
2. 候选创建新记录和新文件；记录视角、参考 ID、原生尺寸、处理类型、交付尺寸、哈希和任务状态。不得覆盖原始正面、认可图或服务原输出。
3. 脚本验收和人工目视检查分别记录。对照具体变更区域与所有回归项，包括用户反复修正的细节，列明观察到的漂移。
4. 用户明确认可后，填写认可范围与时间/私有摘要；只晋升该范围。某个背面的材质认可不等于认可新脸，也不把背面自动升为身份主参考。
5. 用户指定新原型取代基准时，更新 `current_primary` 与 `supersedes`，保留旧记录，重新确认受影响区域。没有新认可时继续保留旧认可成果，把新图列为候选。
6. 失败项归因后，选择最小修正；失败输出不成为下一代的隐式主参考。重复失败时检查实际附图、版本、能力和遮罩，必要时停止低效重试并交代限制。

公开技能更新只保存可复用的方法、匿名失败类别与合成回归测试；用户的认可记录、图像、任务标识和私有反馈留在项目私有工作区。不得把本模板的示例状态当作真实验收。

变更说明至少包括：问题、改变区域、保留区域、实际验证、未验证项、是否需要用户再认可。改动清单结构或脚本参数时写明迁移方法；不因发布新技能版本而重生成或自动替换已交付图像。
