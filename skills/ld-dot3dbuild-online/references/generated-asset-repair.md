# Generated-asset intake and repair

## Establish source and generation accounting

- Preserve the approved reference, exact task ID, generation settings, quoted cost, authorized aggregate budget, and actual charges. Include remesh/texture/retry costs in that same ledger. Poll a known task after a timeout instead of launching a duplicate paid request.
- Check current provider documentation for API versus web-library visibility and retention. Do not promise that API/MCP results appear in the website workspace. Keep provider IDs plus durable downloaded originals; expiring output URLs are not backups.
- For Meshy, use its installed provider skill and current official API/history documentation. Historically API outputs and web Workspace differed and API retention was short; verify current policy instead of embedding a fixed retention period as a guarantee.
- Open the actual downloaded mesh and textures. A reference collage showing five props does not prove five generated objects. Count semantic items, connected components, materials and unwanted bridges; a single prop can have several components and a fused mesh can contain several props.
- If batching, space distinct items clearly with consistent scale cues and uncluttered backgrounds. Verify each requested item after generation. Batch quantity and separability remain uncertain, not a cost-saving guarantee.
- Prefer a usable generated candidate plus targeted repair to repeated blind regeneration when shape is close enough. Procedurally replacing a missing/simple prop is valid when it meets the brief; label its provenance and any visual differences rather than implying every delivered item came from the paid generator.

## Preserve shape and world design

- Treat shape analogies as shape guidance, not permission to copy unrelated surface design. Preserve the approved island footprint and landmarks; cross-check each side against the top view, including the orientation of asymmetric features and the underside.
- Verify silhouettes, open structures, negative spaces, support columns and material assignments on real geometry. A red tower painted on a closed block is not an open platform. Keep reference-dependent landmark height and layout relationships explicit rather than using universal architectural rules.
- Do not describe image-generated four-view sheets as mathematically consistent orthographic drawings. Reconcile conflicting views before or during modeling and label inferred hidden surfaces.

## Reduce density without destroying the asset

- Retain the original high-density mesh and textures separately from optimized candidates. Measure evaluated triangles, material count, texture memory and target-screen quality; a large reduction does not itself make an asset mobile-ready.
- Compare UVs, seams, thin supports, open platforms and small silhouettes after remeshing or decimation. Test a candidate on copies before applying it across a batch. Preserve material boundaries or rebake when topology makes the original mapping unusable.
- Repair only the deficient region when possible. For newly constructed parts, assign coherent UVs/materials and inspect both front and reverse faces instead of relying on original projected textures to cover them accidentally.
- Keep raw output, editable repaired source, optimized/export versions and presentation copies distinct. Use [delivery and playback evidence](delivery-and-playback-evidence.md) for final source/export checks and verified persistent delivery, not a thumbnail or provider success flag.
