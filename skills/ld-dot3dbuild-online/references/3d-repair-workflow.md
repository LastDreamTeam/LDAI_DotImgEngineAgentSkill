# 3D 修复与参考核对

用于按已认可设计修复已有角色资产，包括贴图瑕疵、融合几何、服装层次与绑定前检查。沿用 [创作流程](workflow.md) 的设计冻结和 [迭代约定](iteration.md) 的认可记录。本章是可复用的方法，不是某个模型已修复、已绑定或已通过运行时验收的证明。

内容导航：参考范围 → 问题分诊 → 融合曲面与 shape key → 服装与腋下 → 区域保护与版本 → 重导与视觉核对 → 绑定及交付边界。

## 参考范围与锁定基线

开始前在项目私有记录中标明参考 ID、版本、哈希、用户认可状态、适用视角/部位和禁止影响的范围。用户最新认可的脸、头身比例、轮廓与配色构成锁定基线，不能因发现一个新局部参考而整体回退或重新设计。

| 参考 | 提供的证据 | 使用边界 |
| --- | --- | --- |
| 用户最新认可版本 | 已认可的身份、脸、比例、配色及明确认可的部位 | 按用户认可范围冻结；助手自评和成功导出均不构成认可 |
| 原设及配件分解图 | 服装构造、配件数量、连接关系与原始设计意图 | 不自动推翻用户后来明确认可的脸、比例或配色 |
| 已认可的高分辨率四视图 | 同一设计在正、后、左、右的外观、轮廓与局部覆盖 | 按实际认可范围核对；生成的四视图不自动证明是同一网格 |
| 背面专用参考 | 背部衣片、露背范围、背部连接和遮挡 | 不能替换正面、脸或整体比例，也不能用背面轮廓重塑全身 |
| 局部新模型或试验渲染 | 指定部位的候选几何、材质或修补方案 | 未认可前保持候选；不能作为全身新基线或覆盖既有正确配件 |

参考冲突按用户最新明确指令处理，并记录它覆盖哪个区域。若仍不能判断，只澄清冲突部位，其余基线继续冻结。缺失细节保留当前证据支持的结构并标明未知，不自由补设计。屏幕左右与角色自身左右分开记录。

核对时先打开原设、认可四视图与候选的实际像素，再将它们与同角度模型渲染并排比较。匹配相机朝向、取景、尺度与姿态；可使用正交视图核对比例，透视图检查遮挡。记录哪些差异来自光照、透视、材质或几何，不能仅凭一张远景判定一致。AI 超分辨率参考仍须保留原生来源与放大标记。

## 先分诊，再决定修改层

保留原始材质，使用相同灯光和相机，分别查看中性白模、base color、关闭法线贴图后的材质、normal 与金属/粗糙度通道、线框和 UV。先确认问题来自哪一层，再限定本轮变更；多个原因可并存。

| 现象或类别 | 检查方式 | 对应处理与回归 |
| --- | --- | --- |
| base color 污染 | 白模近看表面连续，彩图却像头发露肤或衣服破洞；检查肤色、黑色烘焙阴影或颜色是否跨入错误 UV 岛 | 确认仅为颜色污染后，局部修贴图与边缘覆盖，保持顶点和 UV 不变；回到彩图近景确认 |
| normal/roughness 残留 | 颜色已修仍发黑；隔离 normal、金属度、roughness，检查网格法线、切线和重叠面 | 修正有证据的问题通道或几何原因；不用涂白遮盖真实缺面、反面或凹陷 |
| UV 接缝与边缘漏色 | 检查内外侧 UV 岛、边线闭合、接缝采样及 dilation/padding；同时看近景与缩小采样 | 修颜色覆盖或 UV 边缘扩张，防止邻岛串色；不能只看远景颜色连续 |
| 真实几何缺失或多余 | 白模、线框、斜视和背面均检查开口、反法线、穿插、双层与多余连片 | 在明确的局部范围补面、重建或移除；保留正确结构、UV 与材质关系 |

头发在白模近景正常而彩图像露肤时，先验证贴图污染，不直接重建整段头发。腋下出现肤色与黑色斑块时，也先查看不受场景光照影响的 base color，区分烘焙污染、真实阴影与缺面；这种现象不能证明所有类似问题均来自贴图。袜口边线必须核对外侧、内侧、绕腿闭合与 UV dilation，远处看似闭合不算通过。对需要保留的真实衣口、分层边界或薄片，不以全模型封闭为目标盲目补面。

## 融合曲面的局部重建

AI 单图生成的模型常是一整片融合曲面，视觉上独立的发辫、衣片、中国结也可能与躯干共用拓扑。删除前检查连通关系、健康表面与附着边界；只移除明确多余的结构，正确配件保持。

不要仅按颜色选面后删除，再用一个中心点扇形封洞。颜色边界未必是拓扑边界，这种补法可能造成黑洞、扇形折痕、瘦长三角形和残根，静态远景容易漏检。

需要重建时：

1. 标出多余结构、受污染过渡区与周围健康边界，保留足够的健康支撑环；确认不会切掉服装或身体的正确部分。
2. 沿健康边界重建局部连续曲面，匹配相邻轮廓、曲率和合理的面密度；避免用大平面盖住弯曲表面。需要新拓扑时只处理该局部，记录与基线的对应关系。
3. 固定或约束边界后做局部平滑，防止收缩身体、移动衣口或改变头身比例。修复后恢复/转移局部 UV、材质槽与边界贴图覆盖，避免全局重投影破坏既有修复。
4. 重查法线方向、退化面、非预期开口、非流形连接、重叠面、自交与接头残根；以白模、线框和原材质近景复核连续性。

若健康边界无法可靠识别，冻结候选并说明重拓扑范围与限制，保留原基线。未查清原因前不继续叠加封洞、平滑和涂色。

## 启用 shape key 时的几何修补

有启用的 shape key 时，只修改 `mesh.vertices` 不保证改动参与实际显示。先记录 Basis、各 shape key 的顶点坐标、相对键关系、启用值和状态，再确定受影响顶点及同一坐标空间下的局部几何 delta。

1. 对需要保留原表情差值的局部平移修补，按需要将同一顶点的 delta 同步加到 Basis 与各 shape key 的坐标中。保留原面部形态差值；对相对 Basis 的键，应保持 `Key - Basis` 不变，相对其他键时也检查对应差值。不要把所有键的坐标直接覆写成 Basis，或通过清除 shape key 使修补显示。
2. 保持原启用值、状态与未改区域，核对修改顶点以外的各键数据不变。若拓扑或索引改变，先建立可靠的旧新对应关系，不能直接复用旧索引批量写入。
3. 更新依赖图，检查实际用于显示的 evaluated mesh，确认局部几何改动已生效且保护区未漂移，再在相同相机、灯光、姿态和 shape key 值下重渲染。几何和材质改动分别保存对照，不能把肤色、阴影或粗糙度改善误归因于几何修复。

## 服装层次、背部与腋下

先依据原设和被认可视图判断身体、独立肩袖、背部衣带及衣片的真实前后关系。对采用背部 V 形衣片的设计，衣片应薄且贴合，末端藏在肩袖后；避免埋进皮肤、穿出袖面，也不能把独立肩袖焊成背带。此形状仅在对应设计有证据时采用，不作为其他角色的默认服装。

用后视、斜后视、左右连接处近景分别检查厚度、遮挡、皮肤间隙与穿插。腋下像破洞的瑕疵先按上表分诊，再按左右两侧分别检查前、侧、斜后和内侧近景；不要直接填满原本应有的袖口间隙。若已有可用绑定，再增加抬手姿态回归；静止时闭合不代表动作中不会裂开。

露背与封闭背部的试验方案分开命名、单独冻结，明确各自来源、改动和验收状态。旧兜底文件保留其旧状态，不能改名后称为已同步新版本；合并方案前先逐项核对差异，不把失败试验带入交付文件。

## 区域保护、冻结与可重现记录

每轮从冻结基线生成候选，只改用户指定部位；局部腋下或背部修复不同时顺手改脸、头身比例、整体配色或其他配件。

- 明确修改区域和不变区域。贴图用同 UV 坐标的区域遮罩与原生分辨率差异检查；网格用顶点/面选区、属性或可追踪的对应关系记录范围。二维截图的保护蒙版不能证明三维网格未变。
- 背面局部修复后，必须补做与基线同相机的正面回归对照，并检查前发等邻近保护区域。记录所属 mesh 和明确的保护面、顶点、loop 索引；误伤时从冻结基线按这些索引恢复对应坐标、shape key 数据、UV/面角数据或贴图区域，并重新比较。索引仅在其所属网格和拓扑版本内有效，变更后需重建映射。不能只凭空间遮罩或背面效果宣称前发无变化。
- 从二维标注投射贴图清理区域时，结合射线命中的材质、面索引、三维位置与深度限定目标，保护投影上相邻但属于其他部件或深度层的表面。衣服旁的长发即使屏幕上很近，也可能处于不同深度；不能只按图像颜色或投影视区扩大遮罩。已发现的失败是扩大衣服清理区域后误染近邻头发；遇此情况先回退误染版本，再收窄目标面和深度范围，单独复查头发与衣服。回退只表示撤销了错误，新补丁仍须重新验证。
- 保持主要 mesh、未修改区坐标、UV、材质分配、贴图与已有修复。局部拓扑调整确有必要时，在变更清单列出新增/删除的面、UV 转移和材质影响，不默默全局重网格化。
- 使用可区分的基线、候选与分支名，例如 `asset-r010-baseline`、`asset-r011-underarm-candidate`、`asset-r011-back-closed-candidate`。文件名不能代替验收状态，不覆盖已认可文件。
- 对输入、原始输出、候选 `.blend`、导出和贴图记录校验和，记录版本来源、允许变化、不变区域回归及未通过项。需要脚本重现时，保留实际执行的脚本、工具版本、参数、输入哈希和输出哈希；涉及随机过程时记录种子及不可重现的限制。
- 用固定相机和灯光保存改前/改后全身四视与局部近景，检查未修改区的脸、比例、正确配件和旧修复。用户验收的是明确的变化清单，候选不自动晋升为认可版。

项目记录、脚本参数中的私人路径和真实资产留在私有工作区。公开经验仅保留可复用方法与抽象示例，不附模型、参考原图、聊天原文、账号、资产分享链接、内部工具说明或服务凭据。

## 保存、全新进程重导与验收

最终候选 `.blend` 保存后，在全新进程中重新打开并导出；不要只验证当前交互会话里的内存状态。再在干净场景或新进程重新导入交付文件，检查实际写入的结果。

| 验证维度 | 应核对的证据 |
| --- | --- |
| 网格与层级 | 对象及层级、变换与尺度、主要 mesh、实际求值后的三角形、局部拓扑差异和修改器的导出影响 |
| 材质与贴图 | 材质槽及分配、贴图数量/尺寸、相对引用或打包状态、颜色与数据贴图解释、UV 和接缝 |
| 骨骼与动作 | 有无预期骨架、骨名/父子关系、权重、动作片段/帧范围，以及导出是否遗漏或意外携带试验动作；不适用时明确注明 |
| 静态视觉 | 相同灯光、相机、姿态下的前后四视对照与局部近景；白模、原材质、背部接头、腋下和袜口分别检查 |
| 动态与目标宿主 | 在实际动作和目标导入环境中检查变形及兼容性；按下一节单独记录结果 |

三角形或材质计数的合理变化须与变更清单对应；计数一致也不证明视觉一致。技术验证与肉眼质量是两个维度，分别写通过、失败、未测及证据。一次保存、导出或重新导入成功，不能据此宣布修复完成。

## 绑定准备、动作测试与交付范围

绑定前识别融合几何与动画拓扑局限，尤其是肩腋、肘、膝、裙摆和头发连接。静止修好不代表抬手和走路不裂，也不代表已具备表情或可独立摆动的头发。

头发焊在衣身时，直接把该连片赋给头骨可能拉扯或撕裂衣身。应明确选择局部分离并重拓扑，或在现有连续曲面上使用保守、连续的过渡权重；记录外观、连接和动画限制，不能承诺独立发束摆动或衣发完全解耦。

动作测试使用实际可用、具有相应使用许可证的动作，私下记录许可来源、使用范围和重定向设置，不以想象的动作名称代替测试。观察肩部抬手、肘膝弯曲、裙摆穿插、脚接触与滑步，必要时逐帧检查。女性步态应根据角色和动作参考评估节奏、重心与落脚，不等于夸张扭胯；不要未经要求额外改变体态。

声称 Unity Humanoid 通过前，必须在 Unity 中实际导入、配置 Avatar 并运行相应动作，核对映射与变形。Blender 内骨骼或动作通过不能代替 Unity 实测；未测试目标宿主时将该项标为未验证。

交付清单分别列出 **外观修复、骨骼、权重、表情、导出、Unity 验证** 的范围、版本、状态与证据，并保留失败或未测项。测试中的腋下修补、绑定或动作分支仍标测试中，不因文档更新被写成已完成。失败试验、旧兜底和认可基线明确区分，交付文件仅包含约定内容。渲染与参考继续如实标注原生分辨率、重采样或 AI 超分辨率；放大输出不称原生高分辨率。
