# Meshy 角色参考图交付

这是本技能维护者确定的角色建模工作约定，不是 Meshy 服务通用的强制上传规格。用户只要其中一个阶段时不擅自扩展任务；上传前另核对当前服务实际接收的格式、尺寸和数量。

## 标准产物与顺序

1. 根据角色原设制作**一张非写实正、侧、背三视图**，用于确定身份、服饰和结构。保留它，不因后来制作写实版就漏交或替换。
2. 从同一已认可设计制作**四张独立的带写实材质感 3D 风格图**：正面、角色自身正左侧、正背面、角色自身正右侧。45° 或四分之三视角只是可选加图，不能代替任何一向。不得拿四格拼图代替四个独立文件，也不得将侧面简单镜像作为另一侧。
3. 按本工作约定交付每张长边 8192 像素、大小不超过 20,000,000 字节的高清版本，保持纵横比。若用户指定其他尺寸/格式，以当前任务为准；不能把竖版硬拉成 7680×4320。非写实三视图的尺寸另行记录，不冒称同样原生 8K。
4. 文件名区分设计三视图、四张 3D 风格图及原始/增强版本。私有清单逐项记录实际尺寸、字节数、哈希、版本、认可状态和处理方式；交付时列明目录路径和可打开的链接。

生成图表现为 3D，不代表已有真实网格，更不是同一网格精确正交渲染。不得因此声称模型已经生成、绑骨或通过 Meshy/Unity 验收。

## 参考角色不能混淆

- 多张参考分别标注“角色身份与服饰”“排版/画风”“结构细节”。参考另一角色的画风不等于替它换发色；身份参考优先于样式参考。
- 实际读取参考图后再传给生成服务。子任务取不到会话图片时，通过授权文件来源恢复原文件，查看后使用明确的文件引用；不靠重试不存在的历史图片索引或凭记忆重画。
- 记录该角色身高、比例和配件位置。具体人物的身高、发髻大小、辫子粗细属于角色回归约束，不成为所有角色的固定值。
- 写实化只改变材质、光照和体积表现，不默认真人化五官、改脸龄、改服装或加配饰。保持同一姿态、全身比例、相机高度、留白与光照基准，方便多视图对照。

## 发型与局部修订

先判断实际连接关系，再调整视觉大小。逐视图核对发髻根部、辫子起点、垂落方向、前后层次和遮挡；背部看到一条辫子不等于它正确连在后脑。复杂非对称发型不能按画面左右随意移动。

用户要求“在这张基础上微调”时，将指定那张设为本轮基线；不要沿用已经过度修正的中间版。只改要求的粗细、比例或位置，保留脸、衣服及其他冻结项。先核对全身轮廓，再放大脸与发饰，最后检查侧背结构；变好看的局部不能掩盖另一视图的身份漂移。

## 角色四视图：用同一个基准逐张核对

1. 给参考图分工：清楚的正面或脸部近照定身份与五官；设定侧背图定轮廓、发束起点、服装接缝和配件的真实位置。标清哪个来源对哪个区域有最终决定权，不用画风参考覆盖已认可的脸。
2. 以认可的 2D 设计做一张正面 3D 风格基准，再用这张基准配合 2D 结构图逐张制作正侧、背面。锁定姿势、头顶和鞋底的垂直位置、材质和光照；只改变观看方向。四张并排检查轮廓、头身比例、手脚朝向和配件，不以文件名代替看图。
3. 逐项记角色自身左／右，例如发饰、腰饰和鞋饰分别属于哪一侧。正面与背面在画面上的左右会互换；侧面没看到某件配饰，先检查是否被遮挡，不为方便展示把它移到近侧。
4. 区分**结构展示**和**自然状态**：2D 背面如把长发拨开以露出衣服，标注它是结构参考。供建模的常态四视图仍保留长发，并核对侧面厚度、背面长度和正面露出的发梢能否对上。
5. 局部修订同时用两个倍率验收：全身图确认改动有实际可见效果，放大原图核对边缘、左右强度和原有五官。只确认看得见且符合要求的项目；已纠正的缺陷在任何一视角复发，都退回该候选修正；其他可用文件可单独交付，但不能把缺项或失败图算入成套通过。

多视图无法确认复杂角色的空间关系时，按[复杂结构先建简模](views-and-layers.md#复杂结构先建简模)校对，再出图。

## 高清不是提示词

- 生成结束后读取文件实际像素。提示词含“8K”而输出仅为 1024×1536，仍须登记为该原生尺寸；不能先上传再宣称已达 8K。
- 需要提升清晰度时优先评估可靠 AI 超分工具，例如 [Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN)，按授权与当前环境选择模型。先用局部/单张试跑，确认耗时、内存和视觉风险，再处理整套。
- 无可用 GPU 不等于任务必然无法完成；可评估 CPU 推理或 CPU Vulkan 路径，但必须实测兼容性与成本，不能保证任何宿主都支持。不得为出图修改系统安全设置或把单台机器的安装步骤变成通用硬要求。
- 已实践过的链路示例：1024×1536 → AI 4×得到 4096×6144 → 保比例重采样至 5461×8192。必须标为“8K AI 增强版”，分别登记 AI 模型/倍率和末段插值；不能叫“原生 8K”或“全程 AI 8×”。此例不是每张图的固定参数。
- AI 超分会补造纹理，也可能改变瞳孔、衣边、发丝和文字。逐张比对原图与增强图，局部检查脸、发饰、衣扣、非对称服装、辫子及细线，发现漂移则换模型/参数或回退，不以更锐利替代更准确。
- 白底 RGB 图可在接收端允许时采用高质量 JPEG 控制体积；需要透明通道时保留支持 alpha 的格式。PNG 超出限额时不要静默降低分辨率或剥离透明度。再次完整解码、读取最终尺寸和字节数，并检查压缩瑕疵。

## 存储与状态

设计三视图、原始四视图、高清四视图和清单分别可辨识，按角色/版本组织在授权目录，不散落根目录。不覆盖唯一原始或认可图；只有上传成功且目标文件可读取，才报告已保存。使用已有清单更新状态，避免不断增加重复“最终说明”。

交付清单至少区分：文件已生成、视觉已检查、已上传、可取回、用户认可。任何一项未完成就写实际缺口，不将另一套角色或相似旧图代为补齐。
