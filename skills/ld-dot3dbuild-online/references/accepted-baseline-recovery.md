# Accepted-baseline recovery and coupled regression

## Recover the correct baseline

- Identify the last accepted revision using delivery IDs, file hashes, source manifests and the user's actual feedback. Do not choose the newest filename alone or mix one revision's model with another revision's evidence.
- Retrieve verified durable source first. Preserve it unchanged and create a new revision for repair. If the exact accepted file is missing, state that fact and distinguish reconstruction from exact recovery; screenshots and scripts do not prove byte-identical restoration.
- Rebuild an acceptance ledger from prior feedback: shoulder pivot, underarm/chest behavior, sleeves, skirt sides, hair/accessory contact and any other specifically accepted behavior. Mark untested items unknown rather than assuming the rebuilt version inherited acceptance.
- When context or a cloud workspace resets, inspect existing outputs and active provider jobs before re-running paid generation or telling the user work is still running. Do not present an old preview or a new approximation as the accepted original.

## Bound changes and test neighboring failures

- Define the smallest editable region and the unaffected invariants before changing it. A chest-weight repair must also test sleeve following; a scarf deformation must also test mouth coverage, adjacent accessories, UV seams and back-side fit.
- Preserve approved body design and other props while fitting a single accessory. A local defect is not authorization to replace the whole character or simplify all materials.
- Compare the same camera, pose, scale, lighting and output revision. Inspect the complete asset after close-up repair so an improved side view does not hide a new front silhouette defect.
- Reopen final saved source and fresh exports after the last edit. Attach current evidence, not screenshots taken before a late geometry/material change.
- Report a concrete remaining defect and the untested scope. Do not convert successful weight normalization, short playback or visual similarity into claims of all bugs fixed, production integration, or restored user acceptance.
