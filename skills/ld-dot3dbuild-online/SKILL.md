# LDAI_Dot3DBuildAgentSkill

版本：1.0.1。原 `ld-dotimgengine-online` 的扩展总入口，保留原图像能力。

将立绘和四视图视为后续建模的输入，而不是与模型修复脱节的终点。
沿用已经验收的成果，只重跑受变更影响的阶段；静态资产不强制绑骨，
刚性穿戴物不强制全身重新蒙皮。技能不提供额外权限，不自动安装工具、
注册服务、创建凭据、购买额度或修改用户的原项目。

## 开工：确定资产合同和已有基线

1. 确认要交付的是参考图、静态模型、刚性配饰、可变形角色或动画成品。
   记录目标软件/版本、尺寸轴向、格式、预算、性能约束、需保留的部位和已认可范围。
2. 查找真实输入和既有交付清单，实际打开图像与模型。不要因 API 列表无结果就
   断言资产丢失；也不把 Git LFS 指针、截图相似角色或过期输出 URL 当成模型本体。
3. 原始文件只读保留，为新修订建独立来源、候选、导出和证据目录。
   若需要恢复已经认可的版本，先读[基线恢复](references/accepted-baseline-recovery.md)。
4. 使用[资产阶段清单](references/asset-pipeline.template.json)记录阶段与证据。
   模板空值不是已完成任务。保留任务 ID 在项目私有清单，不放入公开技能或案例。

## 按阶段推进，不跳过出口检查

| 阶段 | 输入与工作 | 出口门禁 | 失败回退 |
|---|---|---|---|
| 1 参考/立绘 | 用户图、世界观、已认可区域；局部修正、构图和光影 | 实际看图，身份/轮廓/主色与冻结区域符合；记录原生尺寸 | 返回原认可图，改指定区域，不整图漂移 |
| 2 多视图/分层 | 同一设计的顶/侧/底或角色各向视图；明确坐标 | 非对称特征朝向一致，侧面与俯视对应；透明层重新合成可核对 | 先修相机、翻转与设计冲突，不让模型猜矛盾输入 |
| 3 三维生成/建模 | 已核对参考、预算、静态/角色分支 | 实际网格含所需部件、负空间和轮廓，纹理可读；记录实际成本 | 先查已有任务，选可修候选；漏件可局部建模，不盲目重抽 |
| 4 几何/材质修复 | 原生成模型与固定视角对照 | 修正轮廓、结构、UV、材质和接触；未改区域不回退 | 回到保存候选，修局部原因；必要时重做主形，不用纹理掩盖 |
| 5 绑定/试穿 | 角色或需附着配饰；真实身体与关节设计 | 关节位置、权重、形态键/层级正确；配饰各面贴合 | 区分骨位/拓扑/权重/重定向问题，避免全局重绑 |
| 6 动作回归 | 所需动作、姿势和静态对照 | 抬臂、前伸、扭转、下蹲及相关连续区间无新增问题 | 连带复查胸袖、裙侧、接触和UV；保留原已验收范围 |
| 7 导出/录屏/交付 | 最终保存源、导出文件和证据 | 新进程打开/导入通过，实际视频已看，持久副本可取回且校验一致 | 修失败环节或明确限制；不以导出成功/上传排队当成完成 |

分别记录执行态（未开始/执行中/结束/阻塞）与验收结论 `pass/fail/unclear/not_applicable`；
不适用项写理由，只有证据支持才晋升。
用户指定只做某阶段时遵守该边界，不擅自生成模型或花费后续额度。

## 图像与视图分支

- 读取[参考图与立绘](references/image-authoring.md)，按[图像工作流](references/workflow.md)、
  [提示词](references/prompt-templates.md)、[工具编排](references/toolchain.md)、
  [图像验收](references/acceptance.md)和[图像失败案例](references/failure-cases.md)执行。
- 按[视图和透明分层](references/views-and-layers.md)固定顶/底/左右定义与翻转基准。
  顶视图可作为模型生成服务的主图，但不得把它误称海平面正视。
- 参考图多视图不是同一真实网格的正交渲染；标明矛盾和推断。
  输出长边达到 8K 不等于原生 8K 细节，先对齐设计再做高清交付。

## 三维与修复分支

- 读取[生成资产与批量修复](references/generated-asset-repair.md)：任务账本、漏件判断、
  来源披露、减面保UV、API资产保存，以及形状类比不等于照搬其他作品设计。
- 先按[3D 问题分诊与局部重建](references/3d-repair-workflow.md)区分材质污染、法线/粗糙度、UV 与真实缺面，保留已有 shape key 的差值和健康边界。
- 对角色和穿戴物，读取[蒙皮与配饰](references/repair-skinning-and-wearables.md)：
  身体关节而非肩袖支点、胸袖联动、侧裙影响、椭圆围巾、眼镜支架、UV缝和不变量。
- 对静态岛屿/飞船，跳过不需要的骨骼与动作步骤；仍检查底部、开敞平台、轨道、
  薄支撑、朝向和全资产轮廓。需要移动部件时只为指定部件配置合理父级/枢轴。
- 在 Blender 中保留可编辑源；程序化步骤保留可重跑脚本和命名参数。
  不强求将既有手工工程全部重写成代码，也不把只改导出文件当作源工程已修好。

## 验收、保留与交付

- 使用[交付和播放证据](references/delivery-and-playback-evidence.md)区分完整材质源、
  优化候选与录屏副本；检查实际试穿，不仅看道具单体。
- 根据目标格式新进程导入，核对网格/材质、骨架/权重、形态键、动作范围和尺寸朝向。
  静态转一圈不等于动态蒙皮验证，Blender 正常不等于游戏引擎实装通过。
- 持久保存源、纹理、脚本、导出与最终证据，核对上传后大小/哈希并取回关键文件验证。
  保留历史、明确“最新版”，不要再次把临时工作区当永久备份。
- 按[迭代记录](references/iteration.md)登记认可范围。说明具体未修复项和未测试项，
  不声称所有bug已消除，不把从旧版重建说成找回了原验收文件。

## 扩展与兼容

本包包含上述工作方法，可独立给其他 Agent 使用，不依赖私人聊天、账户、模型文件或隐藏工具。
如另装 Blender Character Workflow / Modeling Workflow / Asset Validation / Iterative Refinement，
可按其更完整的建模与检查流程执行；本总入口仍负责跨阶段合同和交付闭环。
原图像脚本 `scripts/png_tools.py` 和分层检查 `scripts/rgba_layers.py` 的接口保留；
分层的具体执行与验证见[透明分层流程](references/transparent-layer-workflow.md)。
旧技能名仅用于迁移识别，新的调用名为 `$ld-dot3dbuild-online`。
